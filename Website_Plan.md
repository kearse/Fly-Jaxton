# JAXTON website plan

## Purpose

Turn visual interest into qualified creative and commercial drone-project inquiries. The website must answer: What does JAXTON do? Is the work relevant to my project? What happens next?

This concept balances creative and commercial audiences equally. The proposed service language is aerial film, photography and site documentation; final scope must be confirmed before launch.

## Positioning and visual direction

Creative perspective, commercial clarity. A contemporary editorial interface: confident typography, architectural whitespace, asymmetric image composition, quiet navigation, and a restrained flight-path line derived from the X. The visual identity remains white/lime on dark and entirely graphite on light. No green accent on the J.

The design uses commercial architecture, site imagery and landscape work to communicate range. Photography is generated conceptual imagery and is labeled as visual studies. It must be replaced or clearly distinguished from actual commissioned work when published.

## Sitemap and page roles

| Page | Purpose | Main content | Primary next step |
|---|---|---|---|
| Home | Explain the offer and establish visual quality | Clear hero, selected perspectives, services, process, studio introduction | Start a project |
| Work | Help visitors find relevant visual examples | Creative/commercial filters and a spacious editorial gallery | Open a project |
| Project detail | Explain the thinking and intended deliverables | Visual-study label, image sequence, proposed brief, approach, deliverables | Discuss a similar project |
| Services | Explain what clients can commission | Film, photography and site documentation; scope and useful inputs | Start a relevant inquiry |
| About | Establish the human approach | Positioning, collaboration principles, project process | Meet through an inquiry |
| Start a project | Collect a useful initial brief | Service, project description, location, timing, name and email | Review inquiry |

## Main visitor journeys

1. Creative buyer: Home > Work > project > inquiry, carrying the project interest into the form.
2. Commercial buyer: Home > Services > site documentation > inquiry, carrying the service selection.
3. Returning visitor: navigation > Start a project, with no mandatory portfolio browsing.

## Homepage sequence

1. Hero: "Perspective, with purpose." Supporting copy explains creative and commercial drone services. Start a project is visible immediately on desktop and mobile.
2. Selected perspectives: architecture, open spaces and commercial site imagery; no fabricated client names or performance claims.
3. Capabilities: three simple rows with concise, useful descriptions and service links.
4. Process: brief, capture, deliver. Scope and output are agreed before capture.
5. Studio: a concise statement about collaboration, linking to About.
6. Closing invitation: start a project, with consistent footer navigation.

## Project-detail template

Introduce the subject, type of study and intended use. Show a full-width primary image, a brief and approach, then a second image. End with intended deliverables and a relevant inquiry link. The prototype example is "Stone & light", explicitly a visual study. It is not a completed client case study. Actual projects should include permission-cleared media and verified facts; do not invent outcomes, flight conditions, credentials or client endorsements.

## Inquiry flow

Short single-page form, optional project-type shortcuts, visible required labels. Required: name, email, service, description. Optional: organization, location, timing. Budget can be discussed after the initial brief. Typed values survive validation errors. A review step summarizes the brief. In this offline prototype, nothing is transmitted; the review screen says so and offers an editable local brief to copy.

Production should add a chosen delivery service, accessible server validation, a real success state, spam controls, privacy notice and operational ownership. No address or backend is invented in this concept.

## Shared design system

- Palette: #10151B dark field, #171C20 graphite, #F4F2EC warm white, #FFFFFF white, #D3F36B signal lime, #A7B5C8 supporting text on dark.
- Typography: a restrained sans-serif hierarchy, large display statements, medium section titles, comfortably sized body copy. The prototype uses local/system sans fonts; recommended brand fonts remain Space Grotesk and Inter.
- Layout: 12-column desktop logic, broad outer margins and generous vertical intervals. Mobile becomes a deliberate single column with preserved hierarchy.
- Components: header, mobile menu, text/arrow actions, primary action, image caption, project tile, service row, process row, form field, validation message, review dialog and footer.
- Identity: original outlined SVG artwork. No raster mockup logo extraction, stretching, recoloring or altered letter spacing.
- Image treatment: natural color, quiet shadows, no rounded card shells, no gratuitous overlays. Alternate full-bleed and inset images for pace.
- Motion: brief opacity/position changes for feedback, disabled when reduced motion is requested. No scroll hijacking, autoplay sound or delayed access to content.
- Accessibility targets: keyboard navigation, visible focus, labeled fields, readable text over photos, meaningful image descriptions and touch-friendly controls.

## Responsive behavior

Desktop: split hero, asymmetric gallery, paired editorial columns, persistent primary navigation. Mobile: simplified menu, headline and action above the image, stacked galleries and full-width form fields. Never shrink a desktop composition to fit a phone.

## Prototype and handoff

The folder contains a responsive HTML/CSS/JavaScript prototype, original logo SVGs, generated photography and desktop/mobile screenshots of the three key page types. It is a Figma-style design review package, not a native .fig file. All text and layout remain editable in the source; the prototype requires no build tools or external font downloads.

## Content needed before launch

- Confirm operating region, final services and preferred inquiry contact.
- Provide a real team introduction and permission-cleared work.
- Supply only verified credentials, insurance or other trust claims you want to publish.
- Confirm project facts, deliverables, media rights and client permissions.
- Connect inquiry delivery, privacy information and analytics preferences.
- Verify domain, trademark and social handles. Availability remains unverified.

## Design review priorities

Review the clarity of the offer, relevance of the work, pacing of the homepage, ease of finding a service, mobile navigation and inquiry flow. Approve the system across the three key page types before extending visual detail further.
